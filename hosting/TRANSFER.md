# Перенос italon-x2.ru

Готовая сборка фирменного салона Italon Experience содержит каталог 993 товаров, фотографии, 42 коллекции с интерьерами и уличными примерами, способы укладки X2, контакты, корзину и коммерческое предложение в PDF. Готовый сайт находится в `public/` и `server/`; исходники — в `source/`.

Сборка рассчитана на Linux-сервер с Docker Engine и Docker Compose v2 либо на хостинг с Node.js 24 и собственным HTTPS-прокси. Для небольшого салона предварительный ориентир — 1–2 vCPU, 2 ГБ RAM и 20 ГБ диска. Нагрузочный тест этих ресурсов не выполнялся. Обычный тариф только с PHP/FTP эту серверную сборку не запускает.

GitHub подходит для хранения кода и обновлений. GitHub Pages не запускает сервер корзины, а для размещения электронной торговли имеет ограничения: https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits . Для этой сборки нужен отдельный сервер или совместимый хостинг.

Новый сервер работает независимо от chatgpt.site, Cloudflare Workers и D1. Корзины хранятся в собственной SQLite-базе на постоянном томе. Каталог, шрифты, изображения и PDF-библиотеки локальные; PDF создаётся в браузере. Сам архив не означает, что перенос завершён: сервер ещё не выбран, DNS не переключён.

## Что нужно для запуска

Название провайдера и оплаченного тарифа, IP сервера, подключённый доступ к серверу/панели и доступ к DNS домена в REG.ru. Пароли в архив не включаются. При отсутствии оплаченного тарифа сначала выбрать и оплатить совместимое размещение.

## Запуск администратором

1. Установить Docker Engine и Compose v2 по инструкции для ОС сервера: https://docs.docker.com/engine/install/ . Разрешить входящие TCP-порты 80/443. UDP 443 используется для HTTP/3.
2. Распаковать архив, например в `/opt/italon-x2`. Веб-доступ должен быть только к `public/`; нельзя публиковать весь каталог архива как корень сайта.
3. Создать `.env` из `.env.example`. В примере указаны `DOMAIN=italon-x2.ru` и `TLS_EMAIL=italon@amanagroup.org`.
4. Проверить конфигурацию и собрать образ:

```bash
docker compose config --quiet
docker compose build app
```

5. Импортировать снимок корзин, если архив содержит `private-data/carts-export.json`:

```bash
docker compose run --rm -T app node server/import-carts.mjs - < private-data/carts-export.json
```

Этот файл содержит анонимные идентификаторы корзин, позиции и версии на момент `capturedAt`. Имена покупателей в корзинах не хранятся. Файл не попадает в Docker-образ и не отдаётся посетителям. Перед переключением нужно получить актуальный снимок со старого хостинга. Импорт не заменяет более новые записи новой базы старыми.

6. Запустить приложение и проверить его до переключения DNS:

```bash
docker compose up -d app
docker compose exec -T app node -e "fetch('http://127.0.0.1:3000/healthz').then(async r => { console.log(await r.text()); process.exit(r.ok ? 0 : 1); })"
```

Ожидается `status: ok`, `catalogItems: 993`. В API настроен фиксированный внешний адрес `https://italon-x2.ru`, чтобы за HTTPS-прокси сохранялись Secure-cookie и проверка происхождения запросов.

## DNS и сертификат

После проверки приложения изменить записи REG.ru на подтверждённый IP нового сервера:

| Тип | Поддомен | Значение |
| --- | --- | --- |
| A | @ | IPv4 нового сервера |
| A | www | IPv4 нового сервера |

У `@` заменить две прежние A-записи `162.159.143.30` и `172.66.3.26` одной записью нового сервера; у `www` заменить прежнюю `95.163.244.138`. Значения описывают последнюю известную конфигурацию — перед изменением проверить текущие записи. Если присутствует AAAA, указать IPv6 нового сервера или убрать устаревшую AAAA после проверки. Оставить DNS-серверы `ns1.reg.ru`, `ns2.reg.ru` и почтовые MX/TXT. Старые TXT-подтверждения платформы не мешают переключению A-записей.

IP нового сервера в комплекте не задан: сервер ещё не выбран. Нельзя использовать примерный или прежний IP.

```bash
docker compose up -d
docker compose ps
docker compose logs --tail=50 caddy
```

Caddy получает и продлевает сертификаты основного домена и www, перенаправляет HTTP на HTTPS и www на основной домен. Для выдачи сертификатов DNS должен указывать на новый сервер, а порты 80/443 быть доступными. Документация: https://caddyserver.com/docs/automatic-https .

DNS-кэши в переходный период могут направлять посетителей на оба хостинга. Сохранить старое размещение до завершения перехода. Снимок корзин не синхронизирует изменения между двумя базами после экспорта; окно фактического переноса нужно согласовать и снять актуальную копию непосредственно перед переключением.

## Проверка после переноса

Открыть сайт с компьютера и телефона через домашнюю сеть и мобильный интернет без VPN. Проверить основной домен и www, фотографии, просмотр интерьеров, фильтры, добавление/изменение/удаление товара, восстановление корзины после обновления страницы и скачивание PDF.

Прежняя корзина восстанавливается при том же домене, сохранённой cookie и импорте соответствующей записи. Другой браузер или удалённая cookie создаёт отдельную корзину. Сайт автоматически не оформляет заказы и не принимает оплату.

## Копии и обновления

База находится в постоянном томе `cart_data`, отдельно от образа. Пересборка и перезапуск контейнера сохраняют данные. `docker compose down -v` удаляет тома: эту команду нельзя использовать для обычного обновления.

```bash
docker compose exec -T app node server/backup.mjs /data/backups/cart.sqlite
docker compose cp app:/data/backups/cart.sqlite ./cart-backup.sqlite
```

Хранить копию отдельно от сервера. Скрипт использует SQLite backup API и учитывает WAL; копировать один открытый `cart.sqlite` вручную не следует. Документация: https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html .

Для обновления заменить готовые файлы новой сборкой и выполнить `docker compose up -d --build app`. Применённые SQL-миграции сохраняются; изменение схемы требует новой миграции. Эта конфигурация предполагает один экземпляр приложения с одной базой.

## Проверки комплекта и ограничения

Локальная проверка использует реальный HTTP-сервер Node.js: каталог и изображения, импорт прежней корзины, HTTPS-cookie за прокси, сохранение после перезапуска, изоляция посетителей, конфликт версий, Origin, ограничение размера запроса и резервное копирование. Проверка интерфейса подтверждает фильтры, галереи и фактическое создание PDF с кириллицей.

В среде подготовки Docker Engine и Caddy не установлены. Запуск контейнеров, публичные сертификаты и доступ из сетей посетителей нужно проверить на выбранном сервере; это ещё не выполнено.
