Ветка: `stage1/integration` = актуальный `main` (`50f714ba`, 6 загрузок: два прайса Listino PDF, три архива фото, файл Яндекс Вебмастера) + вся `stage1/safe-release` (98 коммитов). Ничего не слито в `main`; боевая ветка `ccr-943f3ebb-rcco8n` (`ead91061`), VPS, DNS не затрагивались; `RELEASE_PROMOTION` не включён, ветки `release` нет.

## Слияние
- Конфликт один: `public/yandex_82da83d36b65be39.html`. В версии из `main` в файл попал посторонний `<script>` антивируса Касперского (сохранён с компьютера через браузер); боевой сайт отдаёт чистый файл. Оставлена чистая версия — она **идентична той, что сейчас на боевом сайте**, код подтверждения `82da83d36b65be39` сохранён. Файл в корне репозитория и оба прайса и три архива фото из `main` сохранены без изменений.
- Архивы и прайсы (~90 МБ) попадают в «снимок исходников» сборки, но не в образ Docker (`.dockerignore`), и теперь удаляются из каталога релиза после сборки.

GitHub Actions: все 3 задания зелёные (`d43ae3b1`, `d295efa5`). Docker: настоящая сборка образа и репетиция полной установки/выкладки/отката на локальном Docker (см. `release.md`, §4).

## Реальные блокирующие проблемы
1. **Нельзя гарантировать «в release пишут только Actions»** на личном репозитории — решено переходом на проверку CI на самом сервере (`verify-ci.py`, `release.md` §2, §6). Блокера нет, но ветку `release`/RELEASE_PROMOTION использовать не надо.
2. **Не проверено на VPS Reg.ru:** память 1 ГБ (сборка локально ≈ 180 МБ, рекомендован swap 2 ГБ), свободный диск, сеть до GitHub/Docker Hub, настоящий Caddy. Это можно проверить только `--dry-run` на сервере — нужно ваше разрешение.
3. **Резервные копии не работают, пока вы не дадите:** российское хранилище и `age`-ключ (на вашем компьютере). Без них ставить механизм выкладки не рекомендуется (перед переключением должна быть копия).
4. **ПДн:** политика и согласие — черновики; публикация и включение формы — только после юриста (`legal/`). К выкладке механизма не блокирует.
5. Docker Hub ограничивает частоту загрузки образов (в репетиции `caddy:2` дал 429 из песочницы) — на VPS Caddy уже скачан; новые образы тянет только `node:24-bookworm-slim` при пересборке.

## Решения, которые нужны от вас
Разрешить слияние `stage1/integration` → `main` (после просмотра); разрешить установку на VPS по `release.md` §8; выбрать хранилище копий; юридические вопросы из `legal/pd-audit.md`.
