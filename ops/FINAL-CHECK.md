# Финальная проверка перед внедрением — результат

Работающий сайт, VPS, DNS, настройки GitHub (в том числе Pages), `main` и боевая ветка **не изменялись**. Команды на сервере не выполнялись.

## 1. GitHub Pages
Источник публикации через API настроек получить нельзя (нужны права администратора), но журнал запусков `pages build and deployment` однозначен: **все 32 запуска собраны из ветки `ccr-943f3ebb-rcco8n`** (последний — от коммита `ead91061`), ни одного из `main` и ни одного из веток `stage1/*`. Значит, слияние `stage1/integration` в `main` Pages **не перезапустит**. Побочное следствие: предпросмотр на GitHub Pages привязан к боевой ветке и после перехода на `main` перестанет обновляться; решить, переносить ли его на `main`, нужно отдельно (это настройка Pages, я её не трогал).

## 2. Проверки Actions и `verify-ci.py` на последнем SHA
Три задания: «Тесты, сборка, целостность каталога», «Образ Docker собирается и отвечает», «Браузерные сценарии». Нашлась и исправлена ошибка: GitHub обрезает имена проверок длиннее 50 символов (`…`), из-за чего прежнее длинное имя третьего задания сервер бы не нашёл; задание переименовано в «Браузерные сценарии», а тест `verify-ci.test.mjs` теперь сверяет имена в `ci.yml` и `verify-ci.py` и требует длину ≤ 50. `verify-ci.py` проверен на заглушке API (7 сценариев) и на настоящем GitHub (принимает три проверки `github-actions` на нужном SHA, отклоняет чужую ветку, чужое приложение, незавершённые и проваленные проверки).

## 3. Проверка VPS (только чтение)
`ops/vps/preflight.sh` + `ops/vps/README.md`. Тест `vps-preflight.test.mjs` доказывает отсутствие изменяющих вызовов (белый список `docker`/`systemctl`/`git`/`curl`, файлы песочницы неизменны, секреты не печатаются). Не запускался на вашем сервере.

## 4. Резервные копии в Yandex Object Storage
`ops/backup-yandex.md` (бакет, сервисный аккаунт, rclone без раскрытия секретов, `age` с запасным ключом) и `ops/backup-sizing.mjs`. Оценка: база растёт ≈ 40 МБ в год при 150 корзин и 8 заявок в день; копия ≈ 26% базы; 34 копии за 3 года ≈ 1 ГБ → стоимость 0–0,04 ₽/мес (при «много» ≈ 11 ₽). **Тариф не подтверждён**: страницу прайса я открыть не смог (yandex.cloud недоступен из среды), использованы данные из поиска (1 ГБ бесплатно, ориентир 2,01 ₽/ГБ, запись ≈ 1,39 ₽/1000 операций) — сверить. Реальный размер базы неизвестен.
Исправлено по ходу: на самом сервере теперь хранится 7 копий, а не 34 (`LOCAL_KEEP_*`); настройки `KEEP_*` из `/etc/italon-backup.env` раньше не доходили до скрипта ротации; уведомления не передавали ключ ретранслятора (`X-Relay-Key`) и молча не доходили бы при его включении.

## 5. Совместимость установки с действующим автообновлением
`release.md` §11 и `install-compat.test.mjs`. Найдены и исправлены два конфликта: отдельный замок (теперь общий с прежним механизмом — одновременная выкладка невозможна) и чтение прежнего `/etc/italon-autoupdate.env` (теперь не читается — возврат на прежний механизм не требует правок). Остаются предупреждения: повторный запуск `deploy-reg-ru.sh` включит старый таймер; пока работает прежний механизм, он стирает `compose.release.yaml`; swap 2 ГБ создаёт сам прежний скрипт.

## 6. Чек-лист
`ops/CHECKLIST.md` (A — до сервера, B — диагностика, C — установка без включения, D — переключение, E — возврат, F — чего не делать).

## Что остаётся заблокированным
| Блокер | Кто снимает |
|---|---|
| Сервер не проверен (память/swap/диск, Docker Hub, Caddy, `.env`, размер базы) | вы: запуск `preflight.sh` (или разрешение мне) |
| Нет хранилища копий, сервисного аккаунта и ключа `age`; тариф не сверен | вы |
| Копия и восстановление не проверены на настоящем хранилище | после предыдущего пункта |
| Решение о слиянии в `main` и защите `main` (force-push), 2FA | вы |
| Юридические тексты (политика, согласие, уведомления РКН) — черновики | юрист; установку не блокирует |

## Когда можно переходить к установке
Когда выполнены: (1) preflight без `[ПРОБЛЕМА]`; (2) копии работают, восстановление проверено на вашем компьютере; (3) `stage1/integration` слита в `main` вами и CI на `main` зелёный. Тогда — раздел C–D чек-листа.
