# Подбор керамогранита по описанию и по фото

Страница `/picker/` (в меню «Подбор»). Работает целиком в браузере посетителя: **без платных API и внешних сервисов**, загруженное фото никуда не отправляется (проверяет `tests/picker-e2e.cjs`: за время сценария нет ни одного POST/запроса с телом и ни одного запроса на чужой адрес).

## Как это устроено
| Часть | Где | Что делает |
|---|---|---|
| Описание → подбор | `site/shared/picker-text.mjs` | разбирает русский текст: цвета (в том числе «бело-серый», «светло-серый»), тон, рисунок (мрамор, дерево, камень, бетон, травертин, оникс, однотонный…), поверхность (глянец, мат, структурная…), формат (`60×120`, «большой»), цена («до 5000», «3–6 тыс»), «для улицы» (→ X2), стиль (лофт, скандинавский…), слова из названий и артикул. Цвет и рисунок плиток берутся **из самих фотографий каталога** (по пикселям), а не только из названий. Выдача: баллы + причины («Почему: цвет серый · рисунок бетон · формат 60×120») |
| Фото → подбор | `site/shared/picker-features.mjs`, `picker-browser.mjs` | из выбранной области снимка считает цвет (L\*a\*b\*), цветовую гистограмму, текстуру (рёбра, прожилки, зернистость, направленность без привязки к повороту) и яркость по сетке 3×3; сравнивает с таблицей признаков 1167 фото каталога. Два списка: «Самые похожие» и «Похожий рисунок в других оттенках» |
| Таблица признаков | `data/picker-features.json` (354 КБ, в git) → `public/data/picker.json` | считает `scripts/build-picker-features.cjs` тем же кодом, что работает в браузере (headless Chromium) |
| Страница | `site/pages/picker.mjs`, `site/css/pages/picker.css`, `site/js/pages/picker.mjs` | вкладки, рамка области (мышь, касание, стрелки), карточки каталога с кнопкой «в корзину» |

## Когда пересчитывать признаки
После смены/добавления фото каталога: `npm run picker:features` (нужен Playwright и Chromium) и закоммитить `data/picker-features.json`. Тест `tests/picker.test.mjs` падает, если для какого-то фото нет признаков или фото изменилось.

## Проверено
- `tests/picker.test.mjs` (15): признаки, целостность таблицы, самопоиск 1167 фото (каждое находит само себя), разбор запросов, выдача по реальному каталогу (условия цены/формата/линии выполняются у всех результатов; «чёрный», «белый глянцевый», «бежевый», «зелёный» — по цвету пикселей; «калакатта» и «этернум кофи» — по названию; смягчение невыполнимых условий; враждебный ввод).
- `tests/picker-e2e.cjs` (16, десктоп и телефон): описание, фото, рамка, корзина, адрес `?q=`, разметка во вводе, плохие и огромные файлы, приватность.
- Устойчивость поиска по фото к искажениям (240 фото, поиск по копии, топ-5): исходное 100%, поворот 90° 100%, JPEG-сжатие 98%, размытие 88%, вырезка 60% плитки 87%, яркость ±18% 31–39%, контраст/насыщенность 59%, тёплый свет 57% (при смене освещения «ближайшая» уходит к соседям по тону — поэтому есть второй список по рисунку).

## Ограничения (честно)
- Это сравнение по цвету и рисунку, а не «понимание» картинки нейросетью: оттенки на экранах и в жизни отличаются, интерьерное фото с мебелью лучше обрезать рамкой по плитке.
- Рисунок «мрамор/дерево/камень/бетон» определяется по статистике фото и подсказкам в названиях; редкие случаи ошибаются (например, ребристые панели считаются «деревом»).
- Слова вне словаря («ванная», «кухня») не фильтруют выдачу — подбор по остальным признакам, об этом написано под запросом.
- Не использует облачных моделей; если позже понадобится понимание свободного текста лучше — можно добавить необязательный серверный шаг (с юридической оценкой передачи данных).
