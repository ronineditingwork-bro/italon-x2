# MATERIAL LAB — автоматическое пополнение текстур слэбов 120×278

## Цель
Один локальный конвейер на Windows вместо ручной загрузки каждого артикула:
ARCHITALON (официальные архивы по коллекциям) → папка загрузки →
проверка/SKU/фейсы → оптимизированные WebP/AVIF → MATERIAL LAB →
GitHub → прежнее автообновление сайта.

Крупные ZIP/TIF/PSD **остаются на компьютере**. На VPS, GitHub и в публичный
репозиторий их **не отправлять**. Требуемая папка пользователя:
\`C:\Users\Я\Desktop\Italon-x2\278\`.

## Проверенные данные
- Слэбов в действующем каталоге: **57 уникальных SKU** (транспортный ящик исключён), **16 коллекций**.
- Формат: **120×278 см**; миниатюры каталога ~147–150 × 341 пиксель.
- Получать список **динамически**, а не копировать сюда артикулы:
  \`node scripts/lab-slab-targets.mjs --out=incoming/slabs/targets.json\`
- \`node scripts/lab-slab-targets.mjs --csv --out=incoming/slabs/targets.csv\`
- Официальный ARCHITALON позволяет скачивать архив *коллекции*, *цвета* или *отдельного артикула* и может требовать регистрации.
  Справка: https://blog.italonceramica.ru/ru/novosti-italon/architalon-portal-dlya-dizainerov-i-architektorov/
- Важно: **нет подтверждения**, что официальный портал даёт API/разрешает массовое скачивание. Автоматизацию браузера сначала проверить по условиям доступа.

## Требования к доработке (для локального Claude Code)
1. Разработать \`scripts/lab-slabs-sync.mjs\` с командами
   \`discover\`, \`download\`, \`import\`, \`report\` или один \`sync\`.
   Запуск одной командой из корня проекта. Не завязываться на облачный
   Claude Code — он не видит локальный диск и получает 403 от Яндекса.
2. В режиме \`download\` локально открыть обычный браузер с сеансом
   пользователя: пользователь **сам входит** на ARCHITALON один раз.
   Исследовать законные механизмы сайта; отдавать предпочтение архиву
   *коллекции*, затем *цвета*, и только при необходимости — артикулу.
   Запоминать прогресс в локальном state-файле, не качать уже полученные
   файлы, ограничить одновременные загрузки (например, 1) и делать
   разумные паузы. Не обходить капчи, ограничения доступа, rate limits;
   не хранить пароли или cookies в Git. При запрете автоматизации порталом
   работать с файлами, которые пользователь скачал вручную.
3. В режиме \`import\` рекурсивно сканировать ZIP и распакованные архивы
   в \`278\`, избегать zip-slip, zip bomb, и других небезопасных архивов.
   Поддержать JPEG, PNG, WebP и профессиональные TIFF (в том числе
   многослойные/многофейсовые файлы) с адекватным инструментом
   конвертации, не загружая весь 370-МБ архив в память целиком.
   Нормально обрабатывать отсутствие отдельных файлов: отчёт, пропуск,
   продолжение остальных.
4. Сопоставлять текстуру только с действительным 12-значным SKU/кодом
   из \`targets.json\` по имени/метаданным/официальным данным. Если
   источника или однозначного соответствия нет — **в карантин для
   ручной проверки**, а не случайно присваивать плитке чужой рисунок.
   Подтверждать размер в пропорции 120:278 с допуском, установленным в
   \`scripts/lab-originals.mjs\`. Не допускать транспортный ящик.
   Сохранять provenance (URL портала, архив, имя внутри архива, SKU,
   checksum, дату получения, отделку, число фейсов).
5. Предусмотреть несколько оригинальных *фейсов* для одного SKU, не
   создавать фиктивный bookmatch зеркалированием. В существующем коде
   \`scripts/lab-originals.mjs\` один файл/SKU — расширить схему без
   поломки уже подключённых файлов и не ломая текущий \`/lab/\`.
6. WebP/AVIF: подготовить десктопную и мобильную версии, ограничить
   размер по длинной стороне на основе реальной детализации, сохранять
   естественное соотношение и правильную ориентацию 120×278.
   Публиковать только оптимизированные картинки, с ленивой загрузкой,
   лимитом общего веса и контролем производительности на телефоне.
   Не генерировать 'HD' из 148×341 px искусственным увеличением.
7. \`report\` выводит: всего 57, по каким SKU нашлись исходники,
   у каких сколько фейсов, разрешения, ошибки/неоднозначные имена,
   готово к оптимизации, готово к публикации, суммарный вес.
   Повторный запуск обрабатывает только новые/изменённые файлы.
8. Публикация — через действующий GitHub workflow: отдельная ветка от
   \`ccr-943f3ebb-rcco8n\`, обычный fast-forward после локальных тестов.
   Никаких изменений VPS/Docker/нового CI/системы релизов.

## Права на использование
ARCHITALON предоставляет ресурсы для архитекторов/проектирования,
но **права на публичное размещение изображений как статических
файлов коммерческого сайта не подтверждены**. До письменного
подтверждения/анализа лицензии держать готовые изображения локально:
не загружать на публичный сайт и не пушить в публичный GitHub.
Запрос о праве публикации направлять Italon при необходимости.

## Сделано (конвейер `scripts/lab-slabs-sync.mjs`)
Запуск из корня проекта, Windows, локально:

```
node scripts/lab-slabs-sync.mjs import      # архивы из «Рабочий стол\Italon-x2\278» → проверка → WebP → public/media/lab + data/lab-originals.json + отчёт
node scripts/lab-slabs-sync.mjs report      # отчёт по всем 57 слэбам: incoming/slabs/report.csv и report.json
node scripts/lab-slabs-sync.mjs download    # окно Chrome для скачивания с ARCHITALON (см. ниже)
node scripts/lab-slabs-sync.mjs sync        # download, затем import
node scripts/lab-slabs-sync.mjs assign "<архив>|<файл>" <артикул|skip>   # ручное решение по файлу из карантина
```
Параметры: `--dir=`, `--faces=all` (конвертировать все фейсы), `--publish-faces`, `--no-publish`, `--only=<артикулы>`, `--force`, `--max-total-mb=160`, `--python=`.

- **Файлы:** `lab-slabs-sync.mjs` (порядок работы, состояние, публикация), `lab-slabs-match.mjs` (файл → артикул), `lab-slabs-image.py` (ZIP и конвертация на Pillow, запуск `python -E -P`), `lab-slabs-download.mjs` (загрузчик). Список слэбов — `lab-slab-targets.mjs → slabTargets()`.
- **Рабочая папка** `incoming/slabs/` (в `.gitignore`): `state.json` (оглавления архивов, сделанные конвертации), `decisions.json` (ручные решения), `downloads.json` (происхождение загрузок), `out/<артикул>/<фейс>.webp`, отчёты. ZIP/TIFF в репозиторий не попадают.
- **Безопасность ZIP:** имя записи не используется как путь (распаковка во временный файл), зашифрованные записи, записи больше 1,5 ГБ, со степенью сжатия выше 200 и с `..`/абсолютными путями отклоняются, а число распакованных байтов проверяется по ходу распаковки. Вложенные архивы не распаковываются. Изображение больше 200 Мп не открывается. Распаковывается одна запись за раз, архив целиком в память не читается.
- **Соответствие:** автоматически — только если в имени (архив + файл) есть коллекция и все слова названия (сокращения каталога — по началу слова, русская и латинская запись сравниваются по согласным). Формат в имени файла, если указан, должен быть 120×278. Неоднозначное или неизвестное уходит в карантин, другие форматы — в «пропущено». Транспортный ящик в список не входит.
- **Фейсы:** `F1…F4` из имени файла. Основной — меньший номер; остальные конвертируются по `--faces=all` и публикуются по `--publish-faces` в `faces: [...]` записи `data/lab-originals.json` (сборка проверяет их так же; лаборатория пока показывает основной). Зеркальный bookmatch не создаётся.
- **WebP:** sRGB по ICC, без обрезки и увеличения. Десктоп — до 4615 px по длинной стороне, мобильная копия — 2320 px (если исходник больше). Качество — наибольшее в пределах 1,5 МБ / 400 КБ (не ниже q70); если не укладывается, остаётся q82/q78 и в отчёте ставится пометка. Плита на боку поворачивается на 90°. Общий лимит веса новых публикаций за запуск — `--max-total-mb`.
- **Повторный запуск:** архив узнаётся по размеру и дате, запись — по CRC; уже опубликованное из того же источника не пересжимается. Прогресс сохраняется после каждого файла.
- **Проверено** на 5 скачанных архивах (19 фейсов, все сопоставлены верно, 0 в карантине). Повторная конвертация F1 Статус Кортен совпала с опубликованной до байта по размеру (q78). Карантин, zip-slip, zip bomb, другой формат, повёрнутая плита и `assign` проверены на синтетических архивах; есть модульные тесты в `tests/lab.test.mjs`.

## Загрузка с ARCHITALON: что выяснено
- Без входа портал показывает только форму входа/регистрации; после входа доступны текстуры (по коллекции, цвету или артикулу).
- **Автоматический (headless) заход на italonceramica.ru сразу получает капчу «Вы не робот?».** Обходить её нельзя, поэтому полностью автоматической загрузки нет.
- Условия сайта (п. 3.2) разрешают личное некоммерческое использование материалов; коммерческое использование и публикация допускаются только с письменного разрешения АО «Керамогранитный Завод». Для публикации текстур на сайте нужно подтверждение права (см. README лаборатории: «размещены дилером с правом использования»).
- Поэтому `download` — **полуавтоматический**: открывает видимый Chrome с отдельным профилем (`%LOCALAPPDATA%\italon-x2architalon-profile`, вход запоминается там, в Git ничего не попадает). Пользователь входит, проходит проверку и нажимает «Скачать». Скрипт только сохраняет загрузки по одной в папку `278`, проверяет содержимое по сигнатуре (страница ошибки вместо ZIP отклоняется), не сохраняет дубликаты и записывает URL файла и страницы, дату, размер и sha256 в `downloads.json`. В консоли выводится список недостающих слэбов по коллекциям. После закрытия окна `sync` сразу запускает `import`.
- Нужен Playwright: `npm i --no-save playwright` (package.json не меняется) или `PLAYWRIGHT_PATH`. Браузер — установленный Chrome (`--browser=msedge` или `chromium` — другие варианты).
