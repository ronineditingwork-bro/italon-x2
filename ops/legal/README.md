# Юридические тексты и согласие на обработку ПДн — статус

**Все тексты в репозитории — ЧЕРНОВИКИ для проверки юристом.** Они не опубликованы и не станут публичными случайно.

| Что | Где | Статус |
|---|---|---|
| Политика обработки ПДн | `site/legal/privacy.html` (+ `texts.mjs`) | черновик, поля `[[…]]` не заполнены |
| Согласие на обработку ПДн (отдельный документ) | `site/legal/consent.html` | черновик, поля `[[…]]` не заполнены |
| Анализ маршрута и рисков | [pd-audit.md](pd-audit.md) | справка для юриста |
| Чек-лист инцидента | [incident-checklist.md](incident-checklist.md) | черновик |

## Что включено сейчас

Ничего. Флаги выключены, сайт и форма заявки работают как раньше (проверено побайтным сравнением всех 1290 страниц сборки с боевой версией).

## Как включить — только после одобрения юристом

1. Юрист правит `site/legal/privacy.html` и `consent.html` (заполняются реквизиты оператора, перечень данных, цели, сроки, получатели, трансграничная передача — с учётом выбранного варианта A/B/C из `pd-audit.md`). Увеличить `CONSENT_VERSION` (например, `2026-11-01`).
2. Только тогда: сборка с `PD_CONSENT=1 PD_LEGAL_APPROVED=1` (без `PD_LEGAL_APPROVED` страницы помечены «ЧЕРНОВИК» и `noindex`, а релизная сборка `RELEASE_BUILD=1` падает — защита от публикации непроверенного).
3. На сервере в `/opt/italon-x2/.env`: `REQUIRE_CONSENT=1`, `CONSENT_VERSION=…` (выкладка подхватит их, приложение перезапустится).
4. Если используется ретранслятор Telegram, задать `RELAY_KEY` в Cloudflare и `TELEGRAM_RELAY_KEY` в `.env`.
5. Проверка после выкладки: форма без отметки не отправляет заявку; с отметкой — приходит сообщение менеджеру с пометкой «Согласие получено», в базе заполнены `consent_at`/`consent_version`.

Для включения в браузере/на сборке флаги `PD_CONSENT` — ровно те, что описаны выше; тесты: `tests/legal-consent.test.mjs`, `tests/site-smoke.cjs`.
