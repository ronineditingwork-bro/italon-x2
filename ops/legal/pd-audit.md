# Персональные данные на italon-x2.ru: маршрут, риски, что решить

> **Это техническая справка для юриста, а не юридическое заключение.** Факты о маршруте данных взяты из кода репозитория (проверяемо). Юридические выводы — предварительные, их должен подтвердить специалист по 152-ФЗ. Я не знаю: кто оператор (ИП/ООО, реквизиты), что настроено на сервере и в Cloudflare, какие договоры заключены.

## 1. Какие данные собираются

| Данные | Где вводятся | Обязательность |
|---|---|---|
| Телефон | форма «КП» (корзина) | обязательное поле |
| ФИО (`customer`) | там же | нет |
| Объект/проект (`project`), адрес (`address`), комментарий (`note`) | там же | нет; свободный текст — клиент может написать что угодно |
| Состав корзины (артикулы, упаковки, суммы) | корзина | это не ПДн сами по себе, но связываются с телефоном |
| Идентификатор корзины | cookie `HttpOnly`, 90 дней (случайный токен; в базе только его SHA-256) | создаётся при первом добавлении в корзину |
| IP-адрес, User-Agent | автоматически у Caddy/Cloudflare/хостера | см. §3 |

Аналитики, пикселей, чатов и сторонних скриптов на сайте нет (проверено поиском по исходникам: внешние адреса — только ссылки на карты/соцсети). В браузере в `localStorage` лежит только корзина. Cookie одна — техническая (корзина), поэтому баннер cookie для неё не обязателен, но она должна быть упомянута в политике.

## 2. Маршрут заявки (что происходит при нажатии «Скачать КП / отправить»)

```
Браузер клиента
  │ 1) PDF-КП формируется в браузере (ФИО, телефон, адрес, позиции) и скачивается клиенту
  │ 2) POST /api/quote (HTTPS, multipart: телефон, ФИО, объект, адрес, комментарий, PDF)
  ▼
Cloudflare (если сайт за его прокси — уточнить DNS)           ← возможная передача за рубеж
  ▼
Caddy (Reg.ru VPS, 5.63.152.213) → контейнер app (Node)
  │ a) проверка: телефон, корзина не пуста, лимит частоты, PDF ≤ 2,5 МБ
  │ b) запись в SQLite /data/cart.sqlite (том Docker `cart_data`): created_at, customer, phone, project, note, items, total, [consent_at, consent_version]
  │    — адрес и PDF в базу НЕ пишутся
  │ c) отправка в Telegram: текст (телефон, ФИО, объект, адрес, комментарий, состав) + PDF-документ
  ▼
(по настройке) Cloudflare Worker-ретранслятор (hosting/telegram-relay-worker.js)   ← ПДн проходят через Cloudflare
  ▼
Telegram Bot API (api.telegram.org) → чат менеджера (Telegram, серверы за рубежом)  ← трансграничная передача + хранение в мессенджере
```

Где хранятся копии заявки сейчас:

1. SQLite на VPS Reg.ru (Россия, если VPS в РФ-дата-центре — уточнить у Reg.ru).
2. Чат(ы) Telegram менеджеров (текст и PDF, хранится у Telegram бессрочно, пока не удалят; на устройствах менеджеров).
3. Устройство клиента (скачанный PDF).
4. После внедрения копирования — зашифрованные копии базы на сервере и в российском хранилище (`backup.md`). В копиях только то, что в SQLite.

Журналы: приложение пишет в `stdout` только `quote_received pdf_bytes=N` и тексты ошибок — **без телефона, ФИО и адреса** (проверено по коду `worker/api.mjs`, `hosting/server.mjs`). Docker по умолчанию хранит такие журналы без ограничения срока → рекомендация: `log-opts max-size/max-file` (§6). Журнал доступа Caddy по умолчанию в конфиге не включён. IP может попадать в журналы Cloudflare и хостера.

## 3. Риски по 152-ФЗ (предварительно)

| № | Риск | Серьёзность | Комментарий |
|---|---|---|---|
| 1 | **Нет политики обработки ПДн** на сайте (ст. 18.1 ч. 2: документ должен быть опубликован без ограничения доступа; ст. 18.1 ч. 3 — для сайта) | высокая | Подготовлен черновик `site/legal/privacy.html` (не опубликован) |
| 2 | **Нет согласия на обработку ПДн** перед отправкой формы (ст. 9; с 01.09.2025 согласие оформляется **отдельным документом**, не как часть другой политики/оферты) | высокая | Подготовлен черновик `site/legal/consent.html` + флажок в форме (за флагом, выключен) |
| 3 | **Передача за рубеж (ст. 12):** Telegram (серверы за пределами РФ) и Cloudflare. С 01.03.2023 оператор обязан **до начала** трансграничной передачи уведомить Роскомнадзор о намерении (ч. 3) и оценить принимаемые меры защиты (ч. 5). Для Telegram/Cloudflare «адекватной защиты» страны-получателя юрист должен подтвердить отдельно | высокая | Решение владельца: §5. Уведомление подаётся владельцем (нужны реквизиты и ЭП/Госуслуги) |
| 4 | **Локализация (ст. 18 ч. 5):** первичная запись и хранение ПДн граждан РФ — в базах на территории РФ. SQLite на VPS в РФ — выполняется, если Reg.ru VPS в РФ. Но **Telegram хранит копию заявки за рубежом**, а ПДн ушли в Telegram **после** записи в базу РФ. Практика РКН: допустима последующая передача, но хранение «основной» копии только в зарубежном сервисе недопустимо. Тут граница серая | средняя–высокая | Юрист решает; вариант B (§5) вообще убирает ПДн из Telegram |
| 5 | **Уведомление РКН о начале обработки ПДн (ст. 22)** — по общему правилу обязательно, исключения узкие (ч. 2; например, обработка ПДн только по договору с субъектом). Заявка на КП до заключения договора под исключение, вероятно, не подпадает | средняя–высокая | Владельцу проверить в реестре операторов РКН, есть ли запись |
| 6 | **Поручение обработки (ст. 6 ч. 3):** хостер (Reg.ru), Telegram, Cloudflare, хранилище резервных копий обрабатывают ПДн по поручению или как получатели. Для поручения нужен договор/условия с перечнем действий и мерами защиты; субъектов нужно информировать о поручении | средняя | Реестр обработчиков (§4); договоры проверить |
| 7 | **Свободный текст** (объект, комментарий, адрес) может содержать лишнее | низкая | Подсказка у поля «не указывайте паспортные данные и т. п.» (§6) |
| 8 | **Сроки хранения и удаление:** сроков нет, кнопки «удалить» нет; заявки лежат бессрочно, в Telegram — тоже | средняя | Определить срок (напр. 3 года с последнего контакта) и процедуру удаления/ответа на запросы (ст. 14, 21) |
| 9 | **Журналы:** IP в журналах Cloudflare/хостера; Docker-журналы без ротации; в Cloudflare Workers включённые «Workers Logs» сохранили бы **тело запроса** только при явном `console.log` — в коде такого нет, но настройку нужно проверить | низкая–средняя | §6 |
| 10 | **Утечки и инциденты (ст. 21 ч. 3.1):** при утечке — уведомить РКН в течение 24 часов, результаты расследования в течение 72 часов | процедура | Чек-лист: `legal/incident-checklist.md` |
| 11 | **Безопасность (ст. 19):** TLS есть; приём заявок защищён лимитом частоты; доступ к серверу по SSH — ваш; секреты в `.env` на сервере; копии шифруются; нет списка лиц с доступом и журнала доступа | средняя | Внутренние документы оператора (приказ о назначении ответственного, перечень лиц, модель угроз «в упрощённом виде») — подготовить юристу |
| 12 | Администратор Telegram-чата и менеджеры = «работники с доступом к ПДн» | низкая | Включить в приказ/инструктаж |

## 5. Что владельцу нужно решить (варианты)

**Вариант A — оставить Telegram как канал уведомления** (минимально меняет процесс): до включения формы с согласием подать в РКН уведомление о трансграничной передаче (Telegram, Cloudflare), оформить поручения, указать это в политике и согласии. Остаются риски №3–4 (серая зона локализации, зависимость от иностранного сервиса).

**Вариант B — не отправлять ПДн в Telegram** (рекомендуется юристами, технически уже почти готово): в Telegram уходит только «Новая заявка № N, позиций M, сумма S» с номером заявки; ФИО/телефон/адрес/PDF менеджер смотрит в защищённой странице-админке на сервере в РФ (или получает на e-mail российского почтового сервиса). Требует доработки (админка с авторизацией ~1–2 дня); после этого риски №3–4 по Telegram снимаются. Cloudflare-ретранслятор можно не использовать, если сервер сам достаёт до `api.telegram.org`.

**Вариант C — только российский мессенджер/CRM** (МАХ, Bitrix24, amoCRM) — требует отдельной интеграции и договора.

Для решения мне нужно знать: правовую форму оператора; на каком хостинге/площадке реально стоит VPS; находится ли DNS домена/прокси на Cloudflare («оранжевое облачко»); подавалось ли уведомление в РКН; кто будет отвечать за ПДн (ответственное лицо).

## 6. Минимальные безопасные изменения формы (подготовлены, выключены)

Все — за флагами, по умолчанию сайт **идентичен боевому** (побайтно проверено на всех 1290 страницах сборки):

1. Флажок согласия (не отмечен по умолчанию, ст. 9) рядом с кнопкой, ссылки на `/privacy/` и `/consent/` (`PD_CONSENT=1` при сборке).
2. Без отметки PDF скачивается клиенту локально, но **заявка менеджеру не отправляется**; клиент видит пояснение. Сервер дополнительно отклоняет заявку без согласия (`REQUIRE_CONSENT=1`), поэтому обход через прямой запрос невозможен.
3. В базе сохраняются время и версия текста согласия (`consent_at`, `consent_version`); в сообщении менеджеру — отметка «согласие получено».
4. Подсказка у свободных полей: «Не указывайте паспортные и иные лишние данные» — **не добавлена**, чтобы не менять форму без согласования; предложение к тексту поставит юрист.
5. Рекомендации по эксплуатации (без изменения кода): ограничить размер Docker-журналов (`/etc/docker/daemon.json`: `{"log-driver":"json-file","log-opts":{"max-size":"10m","max-file":"3"}}` — вступает в силу после перезапуска Docker, делать вне часов работы); не включать Cloudflare Workers Logs/Logpush для ретранслятора; включить `RELAY_KEY` в ретрансляторе (код готов), чтобы им не пользовались посторонние; не включать журнал доступа Caddy без ротации и срока.
6. Не сделано (нужно решение): срок хранения и автоудаление; страница/процедура ответа на запросы субъекта; админка (вариант B); баннер cookie (для одной технической cookie не обязателен).

## 7. Что нужно подготовить владельцу вне сайта (для юриста)

- Приказ о назначении ответственного за организацию обработки ПДн; перечень лиц с доступом; журнал обращений субъектов.
- Положение/политика оператора (внутренняя, шире публичной), модель угроз.
- Уведомление РКН об обработке (ст. 22) и о трансграничной передаче (ст. 12) — по решению юриста.
- Поручения/договоры с обработчиками (§4).

## 8. Как проверено

- Маршрут восстановлен чтением кода (`site/js/shop.mjs`, `src/quote.mjs`, `worker/api.mjs`, `worker/quote-lead.mjs`, `hosting/server.mjs`, `hosting/telegram-relay-worker.js`, `drizzle/*.sql`); данные в журналах — поиском `console.*`; сторонние запросы — поиском внешних адресов в исходниках.
- Браузерный тест `tests/site-smoke.cjs` на настоящем сервере: заявка без согласия не уходит, с согласием сохраняется с `consent_at`, прямой POST без согласия → 400.
- **Не проверено:** фактические настройки Cloudflare (прокси/журналы), площадка VPS, содержимое Telegram-чата, договоры, запись в реестре РКН.
