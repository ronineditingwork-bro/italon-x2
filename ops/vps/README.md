# Проверка VPS Reg.ru только на чтение

Скрипт `preflight.sh` собирает сведения о сервере **ничего не меняя**. Он не пишет файлов, не запускает и не останавливает контейнеры и службы, не трогает таймеры, базу, Docker и DNS.

**Что попадает в отчёт и что нет.** Из `/opt/italon-x2/.env` и `/etc/italon-autoupdate.env` — только имена настроек и состояние «задана/пуста» (значения не печатаются; исключение — ветка и адрес репозитория, из которого вырезаны логин, пароль и параметры); адрес ретранслятора Telegram не печатается вообще (только «отвечает ли»); коммиты показываются 12 символами; строки журнала автообновления — последние 5, не длиннее 160 символов. Кроме того, **весь вывод** проходит через фильтр, который маскирует токены Telegram/GitHub, ключи `age`, заголовки Authorization/Bearer, значения для секретных имён (`token`, `secret`, `password`, `key`, …), секретные параметры в адресах, `логин:пароль@` в адресах и любые «непрозрачные» строки длиннее 31 символа. Тест `tests/vps-preflight.test.mjs` подставляет фиктивные секреты во все эти места (и в вывод самих команд) и проверяет, что ни одно значение не попало в отчёт, а диагностика осталась. Это подтверждено тестом `tests/vps-preflight.test.mjs`: все вызовы `docker`, `systemctl`, `git`, `curl` сверяются с белым списком чтения, дерево файлов до и после не отличается.

**Я его на вашем сервере не запускал** — в этой задаче запрещены команды на VPS. Запускать вам (или с вашего явного разрешения мне):

Одна команда в терминале Reg.ru (от root; скрипт скачивается в память и запускается, на диск ничего не пишется; адрес привязан к конкретному коммиту, поэтому содержимое нельзя подменить новым коммитом):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ronineditingwork-bro/italon-x2/<КОММИТ>/ops/vps/preflight.sh) --db
```
`<КОММИТ>` — полный sha проверенного коммита; готовая команда с подставленным значением лежит в `COMMANDS.md` и в сообщении, с которым она выдана. Параметры: `--db` — открыть базу заявок **только на чтение** в работающем контейнере (число заявок, корзин, `quick_check`); `--no-net` — без проверки сети. Результат пришлите (он не содержит персональных данных и секретов), но просмотрите его перед отправкой.

## Что проверяется и что значит результат

| Раздел | Команды (только чтение) | Что искать |
|---|---|---|
| 1. Память, swap, диск | `/proc/meminfo`, `swapon --show`, `df`, `timedatectl`, `dmesg` | swap ≥ 1,5 ГБ (иначе `[ПРОБЛЕМА]`); свободно ≥ 4 ГБ (< 3 ГБ — выкладка откажется работать); OOM в журнале ядра |
| 2. Docker и Caddy | `docker --version/info/ps/images/system df`, `docker compose ps`, `docker inspect` | демон отвечает; `app` и `caddy` в состоянии running, `health=healthy`, число перезапусков; срок сертификата |
| 3. Версия сайта и прежнее автообновление | `/healthz`, `.deployed-commit`, `/etc/italon-autoupdate.env`, хвост журнала | какой коммит сейчас выложен, какая ветка, нет ли ошибок обновления |
| 4. Таймеры | `systemctl list-timers/is-active/is-enabled` | `italon-autoupdate.timer` активен; нового `italon-release-update.timer` быть **не должно** |
| 5. Новые файлы | `ls`/проверка существования | чего уже установлено из нового механизма |
| 6. SQLite | `ls -l` тома, размер `cart.sqlite`; с `--db` — чтение через контейнер | размер базы (для расчёта хранилища копий), число заявок |
| 7. Сеть | `curl` (HEAD/GET), `git ls-remote`, DNS | GitHub и `raw.githubusercontent.com` доступны; `registry-1.docker.io` отвечает 401 (= доступен), остаток лимита Docker Hub; `api.telegram.org` (возможно недоступен — тогда уведомления пойдут через ретранслятор); `storage.yandexcloud.net` доступен |

В конце: число `[ПРОБЛЕМА]` и `[ВНИМАНИЕ]`. Устанавливать механизм можно, когда проблем нет.
